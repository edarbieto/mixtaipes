# ADR-012: English and Spanish from day one via Astro i18n routing

- Status: **Accepted**
- Date: 2026-10-10
- Deciders: Maintainer

## Context and Problem Statement

The audience speaks English and Spanish. Retrofitting i18n later means touching every string. Which mechanism localizes the UI and the LLM-written text?

### Decision drivers

- English default, Spanish second; more locales later without refactoring
- Static Astro build (ADR-002)
- LLM-written text (title, description, why, suggestions) must match the UI language

## Considered Options

| Option | Description |
|--------|-------------|
| A | Astro built-in i18n routing (`/` = en, `/es/` = es), JSON dictionaries per locale shared with the React island; `locale` sent with each turn and passed to the system prompt |
| B | Client-side i18n library with runtime language detection only |
| C | English only |

## Decision Outcome

Chosen option: **A**, because static per-locale routes are free with Astro and keep the React island small.

- Dictionaries: `web/src/i18n/en.json`, `web/src/i18n/es.json`; keys checked for parity in CI (`npm run i18n:check`).
- Default `en`; the root page suggests `/es/` when `navigator.language` starts with `es` (no automatic redirect).
- The mixtape stores its `locale`; every turn sends it; the system prompt instructs the LLM to write title, description, why and suggestions in that locale, regardless of the request's language.
- Refusals and errors are localized in the UI from `refusal_reason` / `error.code` — never LLM or server prose.
- API error `message` fields stay English (developer-facing).

### Positive consequences

- Adding a locale = one JSON file + one Astro config entry.

### Negative consequences

- Two dictionaries to keep in sync (CI check).

### Revisit trigger

A third locale is requested or translations drift despite the check.

## Pros and Cons of the Options

### A — Astro routing + dictionaries

- Good, because of static, SEO-friendly per-locale pages.
- Bad, because of route duplication for each page (only 3 pages: home, share, privacy).

### B — Runtime-only library

- Good, because of a single route.
- Bad, because of a larger bundle and a flash of untranslated content.

### C — English only

- Good, because of less work.
- Bad, because it excludes a core audience.
